# Project notes

- Site for The Sweet Spot (dessert shop, Tripoli). EN + AR with full RTL, routed as `/en/...` and `/ar/...` (root layout is `src/app/[lang]/layout.tsx`; locale config in `src/i18n/config.ts`).
- Public pages: home, about, contact, privacy, order → checkout → confirmation. One branch, Tripoli (Kaslik closed in October 2026); the nav is Menu, Our story, Contact us. The shop's social accounts are in `src/data/site.ts` and show as buttons through `src/components/social-links.tsx`. No payments: orders are saved to Supabase, and the confirmation page has the customer send the whole order to the shop's WhatsApp, written out (`src/lib/order-message.ts`); that's how the shop hears of each order besides the admin's Orders board.
- Domain: thesweetspotlb.com (`site.url` in `src/data/site.ts`). The admin lives at admin.thesweetspotlb.com/admin (`src/app/admin/`, its own root layout and `admin.css`); `next.config.ts` routes hosts. Staff sign in with email + password (Supabase Auth); roles staff < manager < owner (`src/server/admin/session.ts`, enforced again by RLS). `src/middleware.ts` only refreshes admin sessions (edge runtime, `/admin` paths). Plan for the admin, tracking and dashboards: phases 1–6, porting Thirty's tracking stack; Odoo is the ERP (POS, stock, finance), so don't add those tables here.
- Hosted on Cloudflare Workers via `@opennextjs/cloudflare`, deployed by Cloudflare's GitHub integration. Avoid `export const runtime = "edge"`.
- Design references live in `design_handoff_sweet_spot_site/` (start with its `README.md`) and `mockups/`. They are local-only (gitignored) prototypes, not code to copy; recreate the design in React and copy needed assets into `public/`.
- Colours: the twelve official brand colours are the tokens in `src/app/brand-colors.css` (imported by the site's `globals.css` and the admin's `admin.css`). The hex values in the design handoff are outdated (e.g. Blueberry, Cotton Candy); never copy colours from it.
- Scales: section padding uses `pt/pb/py-section-sm|section|section-lg` (tokens in `globals.css`) and every section heading or page title uses `title-section`; menu icons live in `src/components/icons.tsx`.
- Data: public pages read the menu, branches (hours, closures, pause switch, zones) and site settings (home ticker, welcome popup) from Supabase through cached loaders in `src/server/catalog.ts` (tags `menu`, `store`, `settings`; admin saves must revalidate them). `src/data/menu.ts` is the built-in fallback when Supabase isn't configured and the source of the bundled photos (`src/assets/images/menu/<slug>.webp`); uploaded photos live in the `menu` storage bucket. Schema: `supabase/migrations/` (keep it lean), seed: `supabase/seed.sql`, types: `src/lib/supabase/database.types.ts` (`npm run db:types`). Push migrations with `supabase db push` to the linked project; never run Docker or `supabase start`.
- Admin sections (`src/app/admin/(app)/`): orders (live board, history, order page), customers (+ CSV export), menu (items, categories, choices), bundles, prices, offers, site (ticker, welcome popup), store (ordering switch, hours, closures, zones, ETAs), ad tools, connections, health, team. Shared admin UI in `src/components/admin/`; shared server helpers in `src/server/admin/`. Bundles: products of kind `bundle` with slot groups (kind `items`); selections store a pick as `selections[slot] = [itemId]` and its own choices under `"slot/group"`, priced at their usual prices (`src/lib/pricing.ts`). Paid WhatsApp Cloud API alerts (`src/server/order-alerts.ts`, queued by `create_order` for the numbers in the private `order_alerts` setting) are built but off: the client chose the free customer-sent message instead. Their admin card and Health entries appear only once `WHATSAPP_PHONE_NUMBER_ID` and `WHATSAPP_TOKEN` are set.
- Tracking: always call `track()` from `src/lib/tracking` (never a platform's script directly); add new event names to `src/lib/tracking/events.ts` first, or `/api/e` refuses them. Money in tracking params is cents; Meta and Google Ads get food only (`food_value`), GA4 the whole total. The privacy page (`/[lang]/privacy`, copy in the dictionaries) must stay in step with what's collected.
- Scheduled jobs: imports (`supabase/functions/`, Deno; parsing in `_shared/*.ts` is plain TypeScript tested by vitest, entry files are excluded from `tsc`) and the website's `/api/jobs/sweep`. All are started by `run_job()` with a secret kept in Vault (checked with `job_secret_ok()`); never put that secret in a file. Ad results go to `ad_performance`, GA4/Search Console/Instagram/Facebook to `insight_rows`.
- Dashboards (admin home, managers): tabs Overview · Orders · Marketing · Website, each from one database function (`dashboard_orders`, `dashboard_web`, `dashboard_marketing`) called for the period and the one before. Visits and their channel come from `visit_summaries()`; `order_attribution()` credits each order to the last paid ad tap within 30 days, else the last non-direct visit, else direct (visits joined by browser and phone number). Robots, staff browsing (`internal`) and staff test orders (`orders.is_test`) are always left out. Charts are plain SVG in `src/components/admin/charts.tsx` (no chart library, to keep the Worker small).
- Health and ad tools (managers): `/admin/health` (overview from `health_overview()`, problems from `health_problems()`, visit trail; `health_attention()` feeds "Needs attention" on the home page and Health's menu badge via `src/server/admin/health.ts`) and `/admin/ads` (tracking links + QR codes in `tracking_links`, ad/creative/audience names from `src/lib/ad-tools/` saved in `ad_registry`, Meta catalog feed). Public routes outside `[lang]`: `/l/<id>` (short link redirect), `/feeds/meta-catalog.csv`, `/feeds/meta-catalog-ar.csv`, `/feeds/photos/<item>.jpg` (JPEG via the IMAGES binding). A new problem event must be added to `health_bucket()` in SQL to be grouped.
- Ordering: `/[lang]/order` (menu; the customiser opens from `?item=`), `/[lang]/checkout`, `/[lang]/orders/[ref]` (confirmation). Cart: `src/lib/cart.ts` (localStorage). Pricing rules shared by browser and server: `src/lib/pricing.ts`. The checkout server action (`src/server/orders.ts`) prices everything and checks hours, items and the promo code; the database's `create_order` saves the order as priced. Never refuse an order over a website/database mismatch (prices, menu, hours): staff check every order before starting it and sort it out with the customer, so the order must arrive. Until `SUPABASE_SECRET_KEY` is set, development returns demo orders and production refuses orders.
- Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` before committing.
